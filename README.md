# バザーシフト

2日間・各10:00〜15:00の食品バザー向け希望収集・シフト自動作成アプリ。GitHub Pagesで動く、依存パッケージ不要の静的Webアプリです。

## 現在の運用（共有データベース未接続）

1. 管理者が開催日2日間を設定し、希望入力リンクをLINEで送ります。
2. 参加者が名前・学年・30分ごとの参加可能時間・2日間の合計上限・備考を入力します。
3. 参加者は生成された**回答リンクを管理者との個別LINEに返します**。回答は自動送信されません。
4. 管理者が「回答を取り込む」でリンクを貼り付けます。同じ管理者ブラウザーで回答リンクを開いても取り込めます。LINE内ブラウザーと普段のブラウザーは保存先が異なる場合があるため、貼り付けを推奨します。
5. 管理者が役職を設定し、「シフトを作成」を押します。
6. シフト案を確認し、「Notion用にコピー」またはCSVで持ち出します。Markdown表として貼り付けられない環境では、NotionのMarkdownインポートまたはCSVインポートを利用してください。

参加者が同じブラウザーで再回答すると同じIDになるため更新できます。別端末・別ブラウザーで回答した場合は別参加者として扱われるので管理者が重複を整理してください。既存参加者の更新は確認して取り込みます。

## 条件と解釈

- 1日10枠 × 2日 × 3役割＝60枠、必要稼働は30人時。
- 出店責任者・火気取扱責任者を各1人（本科3年以上）登録。そのどちらか1人が各時間帯に配置されます。
- 調理責任者を1人（本科2年以上）登録。調理責任者か調理従事者を各時間帯に1人配置。
- 販売責任者を1人（本科2年以上）登録。販売責任者か販売従事者を各時間帯に1人配置。
- 従事者は本科1〜5年。1人1役職で兼務なし。この解釈は提供された表に基づきます。別の役職兼任規則には未対応です。
- 人数を埋めることを優先し、そのうえで担当時間の偏りを抑えます。合計上限は2日間の合計です。
- 連続勤務・休憩・備考の自然文は自動制約にしません。休憩は参加可能時間から除外してください。
- 人数が足りないときは最大限の配置案を表示し、「未完成」と不足枠を明示します。希望を無視して埋めません。
- 各責任者の登録数・学年に問題がある場合は生成を止めます。
- 日付の変更は回答がないときのみ可能。希望や役職の編集時は古いシフトを破棄します。

## データの扱い

回答・シフトはブラウザーのlocalStorageだけに保存され、GitHubに送信されません。端末を変える際はJSONバックアップを保存・復元してください。データの入ったバックアップや回答リンクを公開リポジトリに追加しないでください。

希望入力リンクに個人情報は含みません。回答リンクには名前・学年・希望・備考を含み、暗号化はしていません。管理者との個別トークで共有してください。URLフラグメントは通常のHTTPリクエストに含まれませんが、リンクを知る人は内容を読めます。ログインや回答者の本人確認はありません。

GitHub Pagesには秘密キーを配置できません。本版は意図的にNotion APIや共有保存先に接続していません。

## 将来の自動収集 / Notion接続

自動収集にはSupabase等の保存先と、管理者認証・参加者ごとの更新権限・公開リンクの権限制御が必要です。参加者は自分の回答だけを登録・更新し、管理者だけが全回答を取得できるようにします。公開キーだけで全回答を読み書きできる構成にしないでください。

Notionへ直接送る場合はサーバー側関数でNotionの秘密キーを管理し、シフトを「日付・開始・終了・責任者・調理・販売」の行に変換します。現在の公開ソースへ秘密キーを埋め込まないでください。

## 開発・公開

Node.js 22以降で `npm test`。ローカル表示は `python3 -m http.server 8000` で http://localhost:8000 を開きます。ビルド不要です。

GitHubのSettings → Pages → Sourceを「Deploy from a branch」、Branchをmain / (root)に設定すると公開できます。更新前にローカルで `npm test` を実行してください。ソースとREADMEも公開されるため、個人情報や秘密キーを含めないでください。
