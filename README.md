# バザーシフト

2日間・各10:00〜15:00の食品バザー向け希望収集・シフト自動作成アプリ。GitHub Pagesで動く、依存パッケージ不要の静的Webアプリです。

## 現在の運用（Supabase接続済み）

1. 管理者セットアップ用リンクを一度開き、開催日2日間を設定して「共有保存を開始」を押します。
2. 表示された管理用リンクを管理者だけで保管し、希望入力リンクをLINEで送ります。
3. 参加者が名前・学年・30分ごとの参加可能時間・2日間の合計上限・備考を入力して送信します。回答はSupabaseに直接保存されます。
4. 管理者画面は約30秒ごとに回答を取得します。「最新回答を取得」でも更新できます。
5. 管理者が役職を設定し、「変更を保存」してから「シフトを作成」を押します。
6. 作成したシフトをもう一度保存し、「Notion用にコピー」またはCSVで持ち出します。

参加者が同じブラウザーで再回答すると、自分の回答を更新できます。別端末・別ブラウザーから回答すると別参加者として扱われるので、管理者が重複を整理してください。

## 条件と解釈

- 1日10枠 × 2日 × 3役割＝60枠、必要稼働は30人時。
- 出店責任者・火気取扱責任者を各1人（本科3年以上）登録。そのどちらか1人が各時間帯に配置されます。
- 調理責任者を1人（本科2年以上）登録。調理責任者か調理従事者を各時間帯に1人配置。
- 販売責任者を1人（本科2年以上）登録。販売責任者か販売従事者を各時間帯に1人配置。
- 従事者は本科1〜5年。1人1役職で兼務なし。この解釈は提供された表に基づきます。別の役職兼任規則には未対応です。
- 人数を埋めることを優先し、そのうえで担当時間の偏りを抑えます。合計上限は2日間の合計です。
- 連続勤務・休憩・備考の自然文は自動制約にしません。休憩は参加可能時間から除外してください。
- 人数が足りないときは最大限の配置案を表示し、「未完成」と不足枠を明示します。希望を無視して埋めません。
- 各責任者の登録数・学年に問題がある場合は生成を止めます。
- 日付の変更は回答がないときのみ可能。希望や役職の編集時は古いシフトを破棄します。

## データの扱い

回答・シフトはSupabaseに保存され、GitHubには送信されません。管理者の未保存の編集内容と、管理用リンクの控えはブラウザーにも保存されます。JSONバックアップには管理用トークンが含まれるため、管理者だけで保管してください。

希望入力リンクに個人情報や管理権限は含みません。参加者が送信した名前・学年・希望・備考は、管理用リンクを持つ人だけが取得できます。参加者は同じブラウザーに保存された編集キーで自分の回答だけを更新できます。ログインや回答者の本人確認はありません。

Supabaseのpublishable keyは公開してよい識別用キーです。データへの権限はデータベース関数と非公開スキーマで制限しています。管理用トークンとイベント作成用トークンはGitHubに保存しません。Notion APIにはまだ直接接続していません。

## Supabaseの初期設定 / Notion接続

`supabase/schema.sql` をSupabase SQL Editorで実行し、別途生成したイベント作成用トークンのハッシュを `bazaar_private.settings` に登録します。テーブルへの直接アクセスはanonymous/authenticatedの両方から拒否し、用途別の関数だけを公開しています。

Notionへ直接送る場合はサーバー側関数でNotionの秘密キーを管理し、シフトを「日付・開始・終了・責任者・調理・販売」の行に変換します。現在の公開ソースへ秘密キーを埋め込まないでください。

## 開発・公開

Node.js 22以降で `npm test`。ローカル表示は `python3 -m http.server 8000` で http://localhost:8000 を開きます。ビルド不要です。

GitHubのSettings → Pages → Sourceを「Deploy from a branch」、Branchをmain / (root)に設定すると公開できます。更新前にローカルで `npm test` を実行してください。ソースとREADMEも公開されるため、個人情報や秘密キーを含めないでください。
